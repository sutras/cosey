# 2026-09-19

## Editor 组件浮动工具栏形态（toolbar="float"）

需求：editor 工具栏按钮太多占地方，增加属性控制工具栏展示形态——默认形态保持不变，新增浮动形态。

### 实现

- `editor.api.ts`：新增 `toolbar` prop（`'default' | 'float'`，默认 default）。
- `editor.tsx`：`toolbar === 'float'` 时不渲染固定 Toolbar，改为在编辑容器内渲染 `FloatFormatToolbar` + `BlockMenu`。
- `float-format-toolbar.tsx`：选中文本后浮出的行内样式工具条（加粗/斜体/下划线/删除线/行内代码/颜色/背景/链接/清除格式），复用 formats/ 下的组件。
- `block-menu.tsx`：鼠标移入编辑器时，光标所在块级元素左侧浮出「+」入口，点击弹出上下文菜单（标题/列表/对齐/引用/代码块 + 插入图片/视频/表格/公式）。
- hooks：`useSelectionRect`（选区 DOM 矩形，只认落在本编辑器的非折叠原生选区）、`useBlockRect`（光标所在顶层块元素矩形；注意 `view.domAtPos` 在块起点返回父容器，必须用 `view.nodeDOM(pos)`）。
- 样式：`editor-float-toolbar.scss`、`editor-block-menu.scss`，在 `style/index.scss` 注册。

### 关键经验

1. **ElPopover/ElTooltip 虚拟锚点必须每次换新对象**：element-plus popper 监听 `reference.getBoundingClientRect` 函数引用 + reference 对象本身的变化来重定位。原地改元素 style 不触发重定位。正确做法：computed 里根据 rect 生成 `{ getBoundingClientRect: () => DOMRect }` 虚拟元素，rect 变 → 新对象 → popper 重建。
2. **ElPopover 默认 min-width: 150px**：窄浮层（如单个 + 按钮）需要 `min-width: 0; width: fit-content` 覆盖，否则按钮离锚点很远。
3. **teleport 到 body 的浮层要算进 hover/dismiss 区域**：块级菜单入口和菜单本体在 body 上，鼠标移过去会触发编辑器 mouseout——hover 判定要把 `.co-editor-block-menu, .co-editor-picker, .co-editor-color-picker` 也算进编辑器范围。
4. **双击选词的时序**：mousedown 先于选区产生，dismiss 判定必须把「点击编辑器内部」视为非 dismiss，否则双击选词后工具条出不来。
5. PM selection 与 DOM selection 可能不同步（点击外部不产生事务），判断「有选中文本」必须两者都查且要求 DOM 选区在 view.dom 内。

### 验证

vue-tsc + eslint 通过；vitepress dev + agent-browser 实测：选词浮出工具条、加粗生效、+ 入口定位正确、菜单弹出且列表/标题操作生效、移出编辑器 UI 消失、点击外部收起、default 形态回归正常。

## 浮动工具栏二轮修改（用户三点反馈）

1. **拖选期间不跟随**：`useSelectionRect` 加 `dragging` 抑制——document 捕获阶段监听 mousedown/mouseup，按下到松开之间 measure 直接 return，mouseup 时补一次测量。工具条只在松开鼠标、选区定型后浮出。双击选词天然兼容（第二次 mouseup 触发显示）。
2. **块级菜单弹右边**：菜单 ElPopover `placement` 从 `left-start` 改为 `right-start`（入口仍在块级左侧，菜单向右覆盖内容区展开）。
3. **「更多」扩展按钮**：浮动工具条末尾加 `…`（RtiMoreHorizontal）按钮，点击弹出扩展面板（ElPopover bottom-end），收纳不常用操作：撤销/重做、字体、字号（含增减）、上标/下标、缩进、源码模式——浮动形态由此覆盖固定工具栏全部功能。
   - 扩展面板 popperClass 带 `bem.b()`（co-editor-float-toolbar），dismiss 判定 `.co-editor-float-toolbar` 选择器天然覆盖它，点面板不收起工具条。
   - 工具条卸载时重置 `moreVisible`（否则下次浮出面板还挂着展开态）。注意 ElPopover persistent：面板关闭后 DOM 仍在，测试要用 offsetParent/display 判可见性而非 querySelector 存在性。
   - `dismissed`（点外部收起）在选区移动到新位置时重置——否则点外部后键盘扩选工具条不再出现。

### 测试方法论教训

- CDP `Input.dispatchMouseEvent` 模拟拖选：`mouseReleased` 的 `clickCount` 必须为 0，否则触发 click 把选区折叠掉，看起来像「代码坏了」实际是测试脚本错了。
- agent-browser 的 console 输出是跨刷新/HMR 累积的历史，grep 到的旧警告不代表当前代码有问题。判定当前代码是否报错：CDP `Page.addScriptToEvaluateOnNewDocument` 注入 error 捕获（轮询 `#app.__vue_app__` 尽早挂 errorHandler）后 reload，看捕获结果。

## 浮动工具栏三轮修复（点击类交互全部失效）

用户反馈三个 bug，根因不同但都属于「teleport 浮层 + document 级监听 + 组件子树耦合」的交互缺陷：

1. **入口按钮点击后消失（菜单打不开）**：点击「+」→ `menuVisible=true` → 入口按钮按 `showEntry = hovering && !menuVisible` 卸载 → 浏览器对被移除元素补发 `mouseout(relatedTarget=null)` → `onMouseOut` 把 `hovering` 和 `menuVisible` 一起清掉 → 菜单刚开就关。修复：`onMouseOut` 开头 `if (!relatedTarget) return`；`menuVisible` 不再由 mouseout 重置（菜单只靠「点外部 mousedown」关闭）。
2. **「更多」面板一闪而过**：内层 ElPopover（非虚拟触发）的 content 有 focus-trap，`onBlur → onClose` 走 `hideAfter=200ms` 定时关闭——焦点在触发按钮上（面板外）就触发。证据是点击后出现 `setTimeout(200)`。修复：**弃用内层 ElPopover，改为内联绝对定位面板**（挂在工具条 popper 内 `.more`），`onDocumentMousedown` 里补「点工具条其他按钮时收起面板」。任何 ElPopover 弹层都别再挂 ElPopover。
3. **link 弹窗点内部就消失**：FormDialog 是工具条 popper 的 **Vue 组件子树**（DOM teleport 不改变组件树）。点 dialog 输入框 → `focusin(input)` → selectionchange → `useSelectionRect.measure` 发现 DOM 选区不在编辑器 → `rect=null` → 工具条整体卸载 → 弹窗连带消失；随后 PM 抢回焦点、工具条重新挂载但弹窗 visible 已随组件销毁。修复：`useSelectionRect` 和 `useBlockRect` 的 measure 开头加冻结守卫——`document.activeElement.closest('.el-dialog, .el-overlay')` 命中就 return。

### 新增测试方法论教训

- **Chrome 153 + CDP 的 `Input.dispatchMouseEvent` 无法合成拖选**（普通 contenteditable 也不行，与产品代码无关）。改用**双击选词**（`clickCount: 2` 的 press+release）制造非折叠选区；`mousePressed` 用 `clickCount:1` 才能落焦点，`mouseReleased` 用 `clickCount:0` 避免 click 折叠。
- ElPopover 关闭后 DOM 仍在（persistent），找元素必须过滤 `getBoundingClientRect().width > 0`，且 popperClass 会累积多个同名隐藏 popper，querySelector 会命中旧的。
- CDP 调试利器：patch `window.setTimeout` 抓 hideAfter 类定时关闭；`document.elementFromPoint` 查点击落点真实元素；从 `el.__vueParentComponent` 沿 parent 链找组件实例（setupState 不可扩展，不能 defineProperty 劫持）。

## 六轮：块级菜单多级化 + context-menu 通用化重构

用户要求块级菜单项太多时做成多级菜单，优先复用/增强 context-menu 组件。确认策略：重构 context-menu 增强通用性 + 全部收进子菜单层级。

### context-menu 增强（4 个能力）

1. **`ContextMenuItem` 支持自定义内容**：新增 `content.api.ts` 的 `ContextMenuContentSlots`（default slot），`content.tsx` 有 slot 时渲染 `content-body`（flex:1）替换 `content-title`；scss 补 `content-body`。这让菜单项能承载任意组件（块级菜单直接复用 Format\* 活组件，保留 active 高亮/下拉/网格）。
2. **`ContextMenuItem` 加 `close-on-select` prop**（默认 true）：内嵌需要继续交互的浮层（heading 下拉、table 网格、image/video/formula 弹窗）的项设 false，点击不关闭菜单。
3. **`ContextMenu` 加 `trigger`（contextmenu/click/manual）+ `virtual-ref` + `placement` + `offset`**：manual 模式下 `open()` 不传坐标时从 virtualRef 的 getBoundingClientRect 取锚点坐标，floating-ui 定位到锚点旁（块级菜单用 right-start + offset 8）。
4. **`ContextMenu` 加 `persistent` prop**：关闭时 v-show 隐藏而非卸载（Transition 包 v-if 的原路径保留为非 persistent 默认）。子菜单通过 `useSubProvide({ persistent })` → `useSubInject().persistent` 跟随根菜单。**close() 时 `hideAllSubs()` 级联收起子菜单**——persistent 下子菜单浮层独立 teleport 到 body，不随根菜单 v-show 隐藏，必须显式 hide，否则残留。

### block-menu 迁移

顶级：标题（FormatHeading 下拉，close-on-select=false）、有序/无序列表、引用、代码块（插槽模式 Format 组件）；子菜单「对齐方式」（4 个 FormatAlign）+「插入」（divided，4 项全部 close-on-select=false）。入口「+」仍是 ElPopover 常驻，onClick 调 ContextMenu.open()。

### 踩坑（重要）

- **JSX children 陷阱**：`<Content>{slots.default?.({})}</Content>` 编译后总创建 slot 函数，Content 的 slots.default 恒存在 → title 文字被空 content-body 顶掉（docs demo 的「复制/粘贴」直接消失）。修复：ContextMenuItem 仅在 `slots.default` 真存在时才传 children 的 vNode，否则渲染不带 children 的 Content。
- **列表内转标题无效是既有行为**：schema `list_item: content: 'paragraph block*'` 要求第一个子节点必须是 paragraph，setBlockType(heading) 不 fit 被拒绝，与本次重构无关（FormatHeading 未改动）。
- **BEM 命名**：ButtonSelect 类名是 `co-editor-button__select`（双下划线），不是 `-`。
- persistent 模式下 popper 遗留 DOM：`.co-editor-format-table__grid` 等会有多个实例，querySelector 要过滤 `getBoundingClientRect().width > 0` 的可见实例。

### 验证

vue-tsc/eslint/prettier 零错误；CDP 实测：多级菜单结构正确（5 顶级 + 2 子菜单）、无序列表点击生效+关闭、对齐子菜单项设置 text-align:center、表格网格 3x3 插入成功、图片 FormDialog 在菜单 persistent 下正常弹出、点 mask 根菜单+子菜单级联关闭；docs context-menu 三个 demo（右键/click/子菜单）无回归。

## 七轮：块级菜单三项修复（滚动跟随 / 图标插槽 / 标题二级菜单）

### 问题 1：滚动不跟随

- `useBlockRect` 只监听 selectionchange/viewVersion，滚动后矩形失效。补 `document scroll (capture) + window resize` 监听重测。
- **Context 菜单本体也要跟随**：原实现 `open()` 时把锚点坐标一次性写入 pointX/pointY（point div 钉死）。修复：`useFloating` 放宽 reference 类型支持 virtual element（`{ getBoundingClientRect }`），ContextMenu 的 reference 改为 `computed(() => virtualRef ?? pointRef)`——锚点模式每次定位实时取坐标。滚动时 useBlockRect 生成新 rect 对象 → block-menu 的 virtualRef computed 重建 → ContextMenu 内部 virtualRef watch → referenceEl 变化 → useFloating watch 重建 autoUpdate（floating-ui 建立时会立即 update 一次）→ 菜单跟随。
- `useFloating` 返回值新增 `update`（暴露 updatePosition），`open()` 重复打开时手动 syncPosition。

### 问题 2：ContextMenuItem / ContextSubMenu 新增 icon 具名插槽

- `content.api.ts` slots 加 icon；`content.tsx` 优先渲染 `slots.icon`（否则回落 icon prop + withIcon 机制）。
- item/sub-menu 的 `itemInstance.icon` 计入 `!!slots.icon`（参与 withIcon 列对齐判定）。
- **大坑：本项目 JSX（@vue/babel-plugin-jsx）对象 children `{{ icon: fn }}` 不会被当作 slots**，会变成 default slot 返回对象 → 菜单项全渲染成 `[object Object]`。必须用 `v-slots={{ icon: () => ... }}` 语法（项目里 Picker 用法可证）。Content 传递 slots 也一律 v-slots。
- 顺带给 ContextMenuItem 加 `active` prop（is-active 高亮，主色文字），command 派发模式下仍能体现当前标题/列表/对齐状态。

### 问题 3：标题从 FormatHeading 下拉改为 ContextSubMenu 二级菜单

- block-menu 重写为 **command 派发模式**：样式类项（标题/列表/对齐/引用/代码块）全部 `ContextMenuItem + v-slots icon + title + command + active`，不再内嵌 formats/\* 组件；`onCommand` 统一分发 `editor.formatHeading/formatList/formatAlign/formatBlockQuote/formatCodeBlock`。
- command 用结构化对象 `{ type: 'heading'|'list'|'align'|'blockQuote'|'codeBlock', value? }`。
- 标题子菜单 = HEADING_WITH_PARA_TYPES（正文 + 标题1~6），active = getActiveHeadingType()。
- render 函数顶部 `void editor.version.value` 建立依赖，块状态变化时刷新 active。
- 插入类（图片/视频/表格/公式）保留 Format 组件（承载 FormDialog/网格），close-on-select=false 不变。

### 验证

tsc/eslint/prettier 零错误；CDP 实测：菜单结构（标题▸/列表/引用/代码块/对齐▸/插入▸ + 图标）、标题二级菜单点标题1 生效且关闭、滚动 120px 入口按钮与块对齐、**菜单打开时滚动 90px 菜单跟随**、无序列表 command 生效 + active 高亮、对齐子菜单居中生效、表格 2x3 插入 + 图片 FormDialog + mask 级联关闭、docs 三个 demo（右键/手动/子菜单）无回归。

## 八轮：FloatFormatToolbar 滚动不跟随（与七轮问题1同源的遗漏）

用户反馈浮动格式工具条（FloatFormatToolbar）不随页面滚动固定在选区上方。根因与七轮 `useBlockRect` 问题1完全同源：`useSelectionRect` 只监听 selectionchange/viewVersion/mousedown/mouseup，**漏了 scroll/resize**——页面滚动时选区本身不变，不会触发任何重测，虚拟锚点 `getBoundingClientRect` 返回旧坐标，ElPopover 停在原地。

修复：`useSelectionRect.ts` 补上与 `useBlockRect` 一致的 `document.addEventListener('scroll', measure, true)`（捕获阶段，覆盖页面滚动 + 编辑器内部滚动容器，且不受 stopPropagation 影响）+ `window.addEventListener('resize', measure)`，onBeforeUnmount 对应移除。

链路：滚动 → measure 重算 rect.value（新对象）→ float-format-toolbar 的 virtualRef computed 重建虚拟锚点 → ElPopover 检测到 reference 变化重新定位。这是「虚拟锚点定位型浮层」的通用必修项：**凡用视口坐标 rect 定位的浮层，必须监听 scroll(resize) 重测，否则滚动即失效**。

## 九轮：浮动 toolbar 在弹窗内失效（冻结守卫误伤外层弹窗）

用户反馈 `src/views/blog/posts/post-upsert.vue` 里 `co-form-dialog`（ElDialog + append-to-body）内嵌的 `editor toolbar="float"` 工具条不出现。

根因：`useSelectionRect` / `useBlockRect` 的 measure 冻结守卫 `active.closest('.el-dialog, .el-overlay')` 命中即 return。这个守卫本意是防「编辑器子树上的子弹窗（link/图片/表格弹窗）打开时工具条连带卸载」，但它把「编辑器本身装在弹窗里」也一并冻结了——编辑器内 `document.activeElement` 永远在 `.el-dialog` 里，rect 恒 null，浮动工具条 + 块级菜单都不出现。

修复：区分「外层容器弹窗」vs「子弹窗」——命中的 dialog 是否包含 `editor.view.dom`：

- 包含 → 编辑器的外层容器，正常测量（不冻结）
- 不包含 → 子弹窗，冻结

```ts
const dialog = active?.closest<HTMLElement>('.el-dialog, .el-overlay');
if (dialog && !dialog.contains(editor.view.dom)) return;
```

两个 hook 同步改。eslint + vue-tsc 通过。通用教训：**判断「是否在弹窗内」做冻结/卸载保护时，必须区分弹窗是编辑器的祖先还是后代**——`closest` 只能证明在弹窗里，`contains(view.dom)` 才能区分方向。

## 十轮：BlockMenu 入口按钮对齐块顶部

用户反馈：长段落光标在上方时，「+」入口按钮被钉在段落垂直中点，会跑到很下面，应改为对齐块级元素顶部。

根因：`block-menu.tsx` 的 `createVirtualRef` 用 `y = (rect.top + rect.bottom) / 2`（垂直居中）做锚点。改为 `y = rect.top`，入口按钮（placement=left）和菜单（placement=right-start）都锚到块左上角，菜单从块顶部向下展开。eslint 通过。

**追加修正（用户反馈「偏上」）**：不是 margin 问题（`getBoundingClientRect` 返回 border-box 不含 margin）。真正原因：入口按钮 `placement="left"` 是**按钮中心对齐锚点**，锚点改到 `rect.top` 后，24px 高的按钮中心落在 top，上半 12px 探到段落上方。修复：入口按钮 placement 改 `left-start`（按钮顶部对齐锚点），与菜单 `right-start`（菜单顶部对齐锚点）统一锚在 `rect.top`。教训：**ElPopover/floating-ui 的 `placement` 不带 start/end 后缀时是沿该轴「居中」对齐，带 `-start`/`-end` 才是边缘对齐**——想让浮层贴某条边，务必用 `xxx-start`/`xxx-end` 而非裸方向词。

## 十一轮：点「+」打开菜单后按钮右移 15px（useLockScroll 布局跳变）

用户反馈：入口按钮距离左边距离应该不变，但点击按钮显示菜单后按钮往右偏移了。

agent-browser 实测复现：点击前 left=338，点击后 left=353（+15px），同时 `body.style.width = calc(100% - 15px)`、`overflow: hidden`。

根因：`ContextMenu` 硬编码 `useLockScroll(visible)`。菜单打开 → 锁滚动给 body 设 `width: calc(100% - 滚动条宽) + overflow: hidden`（本意是补偿滚动条消失防跳动）→ 页面内容重排右移 → 块元素 rect.left 变化 → 锚点重测 → 按钮跟着跳 15px。

修复：

1. `context-menu.api.ts` 新增 `lockScroll` prop（默认 true，保持右键菜单等模态场景兼容）。
2. `context-menu.tsx`：`useLockScroll(computed(() => visible.value && props.lockScroll))`。
3. `block-menu.tsx`：ContextMenu 加 `lock-scroll={false}`——块级菜单是锚定非模态浮层，锁滚动既不合理（用户应能边开菜单边滚动看内容）又引发跳变。

实测验证：点击前后 left 恒 338；body 样式未被改；菜单正常打开；菜单打开时滚动 60px 按钮与菜单同步跟随（358→298）——锁滚动去掉后菜单打开时页面可滚动，且跟随能力（scroll capture 重测）完好。

通用教训：**非模态锚定浮层禁用锁滚动**——lockScroll 的 body width 补偿对「视口坐标锚点 + fixed 定位」的浮层组合就是布局跳变源；模态 dialog/菜单才适合锁滚动。

## 十二轮：插入子菜单统一为菜单项外观（去 format\* 按钮）

用户反馈：`block-menu.tsx` 插入子菜单里图片/视频/表格/公式四项仍是 `Format*` 按钮（`editor-button` 按钮样式），不是菜单项外观。这是七轮「command 派发」重构留下的尾巴——样式类操作已统一成 `ContextMenuItem`，插入类因承载 FormDialog/网格选择器仍复用 `Format*` 组件（它们内部渲染 Button）。

方案：给四个 `Format*` 组件加 `embedded` prop，embedded 模式用 context-menu 的 `Content`（菜单项外观：icon + title + active + onClick）替代 `Button` 作为触发器，弹窗/网格逻辑不变；工具栏用法（不传 embedded）不受影响。

- `context-menu/content.tsx`：`expose({ el: itemRef })` 暴露根元素（表格网格选择器定位锚点用）。
- `context-menu/index.ts`：导出 `Content`（别名 `ContextMenuContent`）。
- `format-image/video/formula.tsx`：embedded 时渲染 `ContextMenuContent`（title + v-slots icon + onClick），FormDialog 不变。
- `format-table.tsx`：embedded 时 `ContextMenuContent` 替代 Button，且 `Picker` 的 triggerTarget 改指向菜单项元素（`contentRef.value?.el`，`onMounted` 里按 `props.embedded` 分流）。
- `block-menu.tsx`：插入四项改为 `<FormatXxx embedded label={...} />`，去掉原 `<ContextMenuItem close-on-select={false}>` 包裹。

### 关键经验

1. **Vue 3 组件 `inheritAttrs` 未设 false 时，`{...attrs}` 展开 + 自动继承会 mergeProps，但同一函数引用会被去重**（`mergeProps` 里 `existing !== incoming` 检查，见 runtime-core.cjs.js ~7734 行），所以 onClick 通过 attrs 透传给 Content 只触发一次，不会双重触发。这也是 context-menu-item 现有 onClick 透传能正常工作的原因。
2. **`expose({ el: ref })` 经 proxyRefs 自动 unwrap**，父组件 template ref 拿到的 `.el` 是值不是 Ref（button.tsx 的 expose 用法同此）。
3. embedded 模式去掉了 ContextMenuItem 包裹层，插入项不再注册进 submenu 的 item 列表——但 Content 自带 CSS `:hover` 高亮、自带 icon，且点击只触发 Format onClick（不 select），天然满足「菜单项外观 + 点击不关菜单」两个需求，比保留 ContextMenuItem 包裹更干净。

验证：vue-tsc --noEmit、eslint、prettier 零错误；vite build 成功（3927 modules）。

## 十三轮：插入后关闭块级菜单

用户反馈：点插入项后上下文菜单还挂着，应该隐藏，只留弹窗/网格继续交互。

方案：给 `Format*` 组件加 `onTrigger` 回调，插入类操作完成/触发时通知 block-menu 调 `menuRef.close()` 收起菜单。按「弹窗类」和「网格类」区分时机：

- **图片/视频/公式**（FormDialog 弹窗，`append-to-body` 独立挂 body）：`onClick` 里先 `onTrigger?.()` 关菜单再开弹窗——弹窗不随菜单隐藏，关菜单无副作用。
- **表格**（网格选择器锚定菜单项）：**选完格子插入后才关菜单**（`onCellClick` 里 `insertTable` 后 `onTrigger?.()`），而非点击菜单项时关——网格锚定菜单项，选择期间菜单必须保持可见才能正确定位。

改动：

- `format-image/video/formula.tsx`：加 `onTrigger` prop，`onClick` 弹窗前调用。
- `format-table.tsx`：加 `onTrigger` prop，`onCellClick` 插入后调用（`onBtnClick` 不调用）。
- `block-menu.tsx`：加 `closeMenu = () => menuRef.value?.close()`，四个 Format 传 `onTrigger={closeMenu}`。

### 关键踩坑（重要，务必记住）

**Element Plus 的 ElTooltip/ElPopover 的 `virtual-ref` + `virtual-triggering` 是配套的，且 ElTooltip 用 `virtual-triggering=true` 会不渲染触发元素（default slot）**。popper 的 trigger 组件 render 是 `!virtualTriggering ? 渲染 default slot : 空注释`。ElPopover 的 default 插槽语义是「content（弹层内容）」而非「触发元素」，所以 block-menu 入口按钮用 ElPopover `virtual-ref + virtual-triggering` 不受影响；但 ElTooltip 的 default 插槽是「触发元素」，用 `virtual-triggering=true` 会让触发元素直接消失（渲染成 `<!--v-if-->`）。

**ElTooltip 只传 `virtual-ref` 不传 `virtual-triggering` 也不行**：实测 grid 定位到页面左上角 (1,1)——`virtualRef` 虽被 popper trigger 的 `watch(props.virtualRef)` 消费并设 `triggerRef = unrefElement(virtualEl)`，但最终 reference 仍回落 default slot 元素，定位异常。**结论：ElTooltip 的虚拟引用定位不可靠，别用它给「触发元素≠定位锚点」的场景换锚点**；这类需求要么改架构（触发元素与锚点分离），要么像本轮表格那样「选择期间保持菜单打开、插入后才关」绕开换锚点。

验证（agent-browser + vitepress docs `editor/float` demo）：图片/视频点菜单项 → 菜单关闭 + 弹窗弹出（插入图片/视频）；表格点菜单项 → 网格锚定菜单项正常展开（526,336 而非 1,1）→ 选 3x3 格子 → 表格插入 + 菜单关闭。tsc/eslint/prettier 零错误。
