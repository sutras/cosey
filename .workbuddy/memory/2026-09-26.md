## 修复：菜单切页吞掉页面 query 参数

**现象**：页面带 query 打开后（如 `/blog/comments?postId=3`），点左侧菜单切到别的页面再切回来，
`?postId=3` 没了；点「当前页自己」的菜单项同样会把参数冲掉。

**根因**：`layout/layout-menu/layout-menu.vue` 的 `onMenuItemClick` 里是裸的
`router.push({ name: item.name })`。vue-router 只按 name 解析 → 得到一个不带 query 的地址，
等于把该页标签页记录过的 `fullPath` 覆盖掉（`layout-tabbar` 的 `afterEach` 会把新地址写回 tab）。
这是 95fbb81 修标签页时留下的同类问题。

**改法**：新增 `packages/cosey/layout/use-route-navigate.ts`，导出 `useRouteNavigate()`：

```ts
export function useRouteNavigate() {
  const router = useRouter();
  const layoutStore = useLayoutStore();
  return (name: string) => {
    const tab = layoutStore.tabList.find((item) => item.name === name);
    tab?.fullPath ? router.push(tab.fullPath) : router.push({ name });
  };
}
```

- 与点击标签页同一套语义（有 fullPath 就按它跳），保证菜单 / 标签 / 搜索三条入口行为一致。
- 目标地址与当前地址相同时 vue-router 判定 `NAVIGATION_DUPLICATED`（v4 `pushWithRedirect` 里
  `isSameRouteLocation` 短路），不重新挂载，所以点当前页菜单项 = 什么都没发生，安全。
- 换用点：`layout-menu`、`layout-snug-menu`、`layout-top-snug-menu`、`layout-search` 四处
  （原来都是裸 push name，全都有同样的 bug）；`layout-tabbar` 里原本手写的 `goto()` 删掉，
  改为复用同一个 composable。
- 文件放在 `layout/` 而不是 `hooks/`：`store/layout.ts` 已经 import 了 `../hooks`，
  hooks → store 会成环；`layout/utils.ts` 里放也行，但那样组件里会同时出现
  `'../utils'`(layout) 与 `'../../utils'`(包级) 两个 utils，容易看错，故单独一个文件。

**验证（agent-browser 真机跑，源码直跑，demo 用 8899）**

- 准备：`NODE_ENV=development ./node_modules/.bin/vite --port 8899 --strictPort`（mock 在浏览器端，
  不需要后端），`admin / 123456`，验证码随便填。
- **重要坑**：agent-browser 守护进程里有多标签页，`open` 之后可能又冒出一个标签（本次是用户自己
  打开的 8882 admin），`eval/click` 作用在「当前活动标签」上 → 表现为「页面莫名回到登录页」。
  先 `agent-browser tab list` 确认活动标签，必要时 `tab t1` 切回来 / `tab close tN` 关掉多余标签。
- 计数办法：`eval` 里桩掉 `history.pushState/replaceState` 记到数组；DOM 侧用
  `.el-menu-item:has-text('X')` / `.el-sub-menu__title` 派发 `MouseEvent('click',{bubbles:true})`
  比快照拿 ref 稳（ref 会因重渲染失效）。整段交互写在一个 `eval` 里 `await`（eval 支持 Promise），
  避免中间被别的标签夺走焦点。
- 结果：`#/users?id=123&name=abc` → 点 工作台 → 点 用户管理 ⇒ 回到 `#/users?id=123&name=abc`
  （navs 里最后一次 `pushState:#/users?id=123&name=abc`）。
- 对照：`$router.push({ name: 'Users' })`（= 修复前的写法）⇒ `#/users`，参数确实被清空。
- 点「当前页自己」的菜单项 ⇒ 0 次 push，地址与 tab.fullPath 均保持原样。
- 未打开过的页面（分析页）⇒ `#/dashboard/analysis`，无脏参数、单次 push。
- 标签页切换（复用了新 composable）⇒ `#/users?id=123&name=abc`，未回归。
