## utils/file.ts：downloadAttachment 支持 fetch 的 Response

**改动（`packages/cosey/utils/file.ts`）**

- 签名从 `(response: AxiosResponse)` 改为 `(response: AxiosResponse | Response)`，函数改为 `async`
  （Response 的响应体只能异步读，`await response.blob()`）；axios 调用方不 await 也能继续跑。
- 新增内部工具：`isFetchResponse()`（`typeof Response !== 'undefined' && instanceof`）、
  `getHeader()`、`parseFilename()`。
- `getHeader()` 统一读头：headers 上有 `get` 方法就调 `.get(name)`（Headers / AxiosHeaders 都提供，
  且不区分大小写），否则按 key 直接取（axios 的普通对象响应头）。
- `parseFilename()` 修了老的解析 bug：原来 `split('filename=')` 在 `filename*=UTF-8''...`（RFC 5987）
  或没有 filename 时要么崩、要么把 `x.pdf; filename*=UTF-8''...` 整串当文件名。现在先匹配 `filename*=`，
  再退回 `filename="..."`，并按 `;` 截断；`decodeURIComponent` 包 try/catch（避免 `100%.pdf` 抛错）。

**验证方式（脚本临时放仓库根目录跑完即删，未提交）**

- 桩 `document.createElement` / `URL.createObjectURL` 抓 Blob，`./node_modules/.bin/tsx` 直接跑，
  覆盖：axios + 普通对象头 / axios + AxiosHeaders / 只有 content-type 的兜底名 / 无头 /
  `options.filename` 优先 / 原生 `Response` / Response 兜底名 / 非法转义 / 老写法回归 —— 14 条全过。
- 反证：把旧实现原样搬进脚本喂 `Response`，得到「文件名 download、type 空、内容 "undefined"」，
  确认新断言不是恒真。
- 类型：`tsc --noEmit --strict --lib esnext,dom,dom.iterable` 跑调用方脚本（同时检查 file.ts）通过；
  prettier、eslint（`--max-warnings 0`）均通过。docs 下没有 utils 文档页，无需同步文档。

## 后续：parseFilename 改名导出为 getDispositionFilename

- 私有 `parseFilename()` → 公开 `getDispositionFilename(contentDisposition?: string | null)`，
  放在 `createBlob` 之后（与其它公开 util 排在一起，私有 helper 集中在 `downloadAttachment` 上方）。
  私有 helper 区（`AttachmentResponse` / `isFetchResponse` / `getHeader`）保持不导出。
- 参数放宽为 `string | null | undefined`，解析不到返回 `''`，所以可以直接把
  `headers.get('content-disposition')` 的返回值丢进去。
- 公开后顺手放宽了等号两侧的空格：`/filename\s*=\s*"?([^";]*)"?/i`（`filename = "x.pdf"` 也能解，
  老写法 `split('filename=')` 解不了）。注意 `filename\s*=` 不会误吃 `filename*=`，因为 `*` 卡在 `=` 前。
- 「全局导出」不需要动 `utils/index.ts`：那里已经 `export * from './file'`，导出即全局可用
  （运行时确认 file.ts 的导出里有 `getDispositionFilename`）。
- 验证：18 条断言（引号/无引号/空格/大小写/`filename*` 优先/非法转义/inline/缺失/undefined/null/空串/
  `Headers.get()` 直传 + downloadAttachment 双路径回归）全过；`vue-tsc -p tsconfig.app.json` 的
  10 条报错全在 editor/format-\*.tsx 与 src/views/**（**仓库既有问题，与本次无关\*\*），utils/file.ts 零报错。

**坑**

- `new AxiosHeaders().set('Content-Type', x)` 的 own key 保留原始大小写（`Content-Type`），
  所以 `headers['content-type']` 取不到；真实响应经 axios 处理后 key 是小写才碰巧能取到。
  要兼容手工构造的 AxiosHeaders，必须走 `.get()`（不区分大小写）。
- undici 的 `Response` 不允许 header 值出现非 ASCII（ByteString 限制），测试里中文文件名要用
  `filename*=UTF-8''%E4%B8%AD...` 形式，否则 `new Response()` 直接抛错。
