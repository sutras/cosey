## utils/file.ts：downloadAttachment 支持 fetch 的 Response

**改动（`packages/cosey/utils/file.ts`）**

- 签名从 `(response: AxiosResponse)` 改为 `(response: AxiosResponse | Response)`，函数改为 `async`
  （Response 的响应体只能异步读，`await response.blob()`）；axios 调用方不 await 也能继续跑。

  且不区分大小写），否则按 key 直接取（axios 的普通对象响应头）。
- `parseFilename()` 修了老的解析 bug：原来 `split('filename=')` 在 `filename*=UTF-8''...`（RFC 5987）

  再退回 `filename="..."`，并按 `;` 截断；`decodeURIComponent` 包 try/catch（避免 `100%.pdf` 抛错）。

## layout-tabbar：修「带 query 跳转后被二次跳转吞掉 query」

**现象**：`src/views/dashboard/workspace.vue` 里 Tiny 加的测试按钮 `router.push({ path: '/users', query: { id: 123, name: 'abc' } })`，
URL 会先到 `/users?id=123&name=abc`，紧接着变成 `/users`。

**根因（`packages/cosey/layout/layout-tabbar/layout-tabbar.vue`）**：
`router.afterEach` 会把 `layoutStore.activeTab = to.name`，而这个赋值又触发了 `watch(activeTab)` →
`router.push({ name: activeTab })`。第二个 push 只有 `name`，所以 query / params / hash 全丢。
即「路由 → activeTab → watch → 再 push」的回环，任何带 query 的导航都会被吞掉一次。

**改法**：watch 回调里加 `if (name === route.name) return;` —— 路由同步过来的赋值与当前路由必然同名，
直接跳过；只有用户点标签页 / 关闭标签页导致 activeTab 与当前路由不同名时才 push。

**验证（agent-browser 真机跑，不是脑补）**：

- `NODE_ENV=development ./node_modules/.bin/vite`（`server.port` 写的是 8882，被占就顺延到 8883；
  这次起来了 8883）。mock 是浏览器端 `@cosey/mock`（Dexie + IndexedDB，首访 `initSeed()` 自动灌数据），
  不需要起任何后端。登录账号 `admin / 123456`，验证码随便填（mock 的 `/auth/login` 不校验验证码）。
  登录后落在 `/#/dashboard/workspace`（hash 路由）。
- 计数办法：`agent-browser eval` 里桩掉 `history.pushState` / `replaceState` 记账到 `window.__navs`，
  点完再读。修复前 = `["#/users?id=123&name=abc", "#/users"]`（两次 push），修复后 = 单次 push 且 query 保留。
- 回归全部通过：点标签切换（1 次 push）、关闭当前标签（跳相邻、1 次 push）、关闭非当前标签（0 次 push）、
  右键菜单「关闭其他 / 关闭右侧」（各 1 次 push）、标签栏刷新按钮（0 次 push）。
- 标签 DOM：`.el-tabs__item[id="tab-<路由名>"]`（路由名首字母大写，如 `tab-Users`），
  `.is-icon-close` 是关闭按钮，右键锚点是 `.co-layout-tabbar__context-menu-reference`（bem 前缀是 `co-`）。

所以「切走再点回同一个标签」仍会回到不带 query 的地址（属既有设计，非本次回归）。
要修的话得给 `LayoutTab` 加 `fullPath` 并在 afterEach 里同步。

## build 脚本的类型检查从「空转」改成真检查

Tiny 问 `"build": "vue-tsc && vite build"` 改成 `vue-tsc -p tsconfig.app.json` 如何 —— 方向对，
但先说清现状：**现在的裸 `vue-tsc` 什么都没查**。

- 证据（故意写错文件实测）：`src/` 放 `export const probe: number = 'x'`，
  - 裸 `vue-tsc` → exit 0、零输出（空转）；
  - `vue-tsc -p tsconfig.app.json` → 报 TS2322；
  - `vue-tsc -b` → 报错，且 `scripts/tmp-probe-node.ts` 也能报出来。
- 原因是根 `tsconfig.json` 是 `"files": []` + `references` 的 solution 式配置，
  **不带 `-b` 时 TS 不检查被引用的 project**。所以旧 build 脚本里的类型检查一届于零。
- 最终改成 `"build": "vue-tsc -b && vite build"`：比 `-p tsconfig.app.json` 多覆盖了
  `tsconfig.node.json` 的 `vite.config.ts` / `plugins/**` / `scripts/**`，耗时却基本一样
  （`-b` 冷 8.24s、热 7.39s；app-only 7.45s）。

## 第三方消费报错 `Prism is not defined`（prismjs 语言包依赖全局）

Tiny 报：第三方用 cosey 时报 `Uncaught ReferenceError: Prism is not defined`。

**根因**：prismjs 的**语言包**（`prismjs/components/prism-*.js`）不是 ES 模块，是直接读全局 `Prism`
的脚本（`Prism.languages.scss = Prism.languages.extend(...)`）。而全局 `Prism` 只由核心 `prism.js`
的 UMD 尾巴建立（`_self.Prism = _` / `global.Prism = Prism`）。所以语言包能不能注册成功，取决于
「它求值时全局 Prism 是否已经建立」。cosey 原来是 `import Prism from 'prismjs'` 裸引核心 +
一串语言包，**把这件事交给外层打包链路决定**：

- 仓库内 app / 消费者项目默认链路：core 没被摇掉、顺序也对 → 正常（39~41 个语言）。
- 一旦打包器把核心的全局挂载摇掉、或调整了求值顺序（tree-shake、预打包 chunk 拆分、
  多入口共享 chunk），语言包就炸。

**复现**（关键，不靠推断）：造一个「敌意核心」——`prism.js` 副本删掉 `_self.Prism = _;` 与
`global.Prism = Prism;`、补 `export default Prism;`，用 vite `resolve.alias` 把 `prismjs` 指过去：

- 仓库 app dev：`import('/packages/cosey/components/highlight/highlight.api.ts')` → `ERR: Prism is not defined`；
  `editor/pm/prism.ts` 同样。
- 消费者项目（吃 `lib-dist/cosey`）首屏 init-script 抓到 `Uncaught ReferenceError: Prism is not defined`，
  栈顶就在 Vite 预打包 chunk 的语言包注册处 —— 与 Tiny 报的一字不差。

**修复**：新增 `packages/cosey/utils/prism.ts`，在语言包之前显式建立全局：
`import Prism from 'prismjs'` → `if (!globalThis.Prism) globalThis.Prism = Prism` →
`export const prism = globalThis.Prism ?? Prism`。
`highlight.api.ts` 与 `editor/pm/prism.ts` 改成「先 `import { prism } from '.../utils/prism`、再 import
语言包」，运行时读 `prism.languages` / `prism.tokenize`（不再依赖全局），对外导出改 `export { prism as Prism }`
保持 API 不变。守卫写 `if (!…)` 是**刻意**的：外部已有全局时沿用它，保证「注册进去的对象」和
「读的对象」是同一个。

**验证**（同一敌意环境下 + 全部常规链路回归）：

- 两处模块导入 → `ok`；消费者首屏（先清共享 `node_modules/.vite`、全新浏览器会话）→ `window.__errs` 空、
  `window.Prism` 含 scss/typescript/tsx/nginx、`#app` 渲染出 `<span class="token keyword">const</span>`。
- 回归：消费者正常配置 39 个语言正常；仓库 app dev 41 个；文档站 5176 `/components/highlight` 0 报错、
  37 个 token；编辑器 `prismPlugin.spec.state.init` 对 tsx/python 代码块产出 20 个装饰，
  class 含 `token keyword|operator|builtin|number|function`。
- 消费者生产构建成功，产物里能看到 `globalThis;Xy.Prism||(Xy.Prism=RP);const Gm=Xy.Prism??RP`。

**坑**：

- `node_modules/.vite/deps` 是**共享**预打包缓存，消费者项目也读它 —— 复现/验证前必须先删，
  否则会读到旧 chunk 得出假结论。
- `scripts/cosey:build`（`tsx ./scripts/build.ts`）内部的 `vue-tsc` 要求 PATH 里有它，本机 pnpm 不在
  PATH，得垫 `/tmp/bin/vue-tsc` 垫片（`exec .../node_modules/.bin/vue-tsc "$@"`）再跑。

**改动未提交**：`M packages/cosey/components/editor/pm/prism.ts`、
`M packages/cosey/components/highlight/highlight.api.ts`、`?? packages/cosey/utils/prism.ts`。
收尾已清掉临时文件（tmp-consumer / tmp-prism-stub / tmp-vite-stub.config.ts / tmp-build-cosey.ts）
与所有后台 dev server（8892/8894/8896/8897/5176），`agent-browser close --all`。

## 收敛 prism 语言包清单（顺手修掉 highlight 的 python 静默降级）

Tiny 问：`editor/pm/prism.ts` 和 `highlight/highlight.api.ts` 对 `prismjs/components/*` 的导入是否重复、
可否优化掉。

**静态结论**：是重复的。两份清单 14 / 15 个，交集 13；各自独有 python / (json5 + nginx)。
但**运行时和产物体积都不重复** —— ESM 模块只求值一次，打包器也会去重成共享 chunk。
所以这不是性能问题，是维护问题。

**但顺着查出一个真 bug**：`highlight.api.ts` 的 `Lang` 里声明了 `LangPython = 'python' | 'py'`，
清单里却没有 `prism-python`。写探针只导入 highlight 入口实测 → 39 个语言，`python` / `py` 都 MISSING；
组件是 `Prism.languages[lang] || Prism.languages['text']`，所以 `<Highlight lang="python">`
**静默降级成纯文本，不报错**。一直没暴露是因为 app 同时用了编辑器，编辑器的清单顺手带进了 python
（app 里 41 = 39 + python + py）。

**做法**：拆两层、清单只留一份。

- `utils/prism.ts`：保持原样，只建全局 + `export const prism`，**不装语言包**（注释里写明「业务要用
  prism 请引 ./prism-langs」）。
- 新增 `utils/prism-langs.ts`：第一行 `import { prism } from './prism'`，之后 16 个语言包
  （两份清单的并集：+ python / json5 / nginx），末尾 `export { prism }`。
- 两个使用方各减成一行 import，删掉各自的清单与「顺序不要调整」注释。

**为什么必须两个文件**（本来是打算合成一个的）：同一模块内所有 `import` 都在模块体之前求值，
守卫写在模块体里就排在语言包之后。实测反证过：`import 'prismjs/components/prism-scss'` 写在
`import { prism } from './utils/prism'` 之前 → `ReferenceError: Prism is not defined`。
所以「守卫先于语言包」只能靠模块间的顺序保证。

**验证**：

- 契约探针：`Lang` 里 36 个字面量 + editor `languageOptions` 16 个，缺失 0（改前 python/py 缺 2）。
- 敌意环境（把 `prism.js` 副本的 `_self.Prism = _;` 删掉、`module.exports = Prism` 改成
  `export default Prism`，vite `resolve.alias` 用正则 `/^prismjs$/` 精确替换）：
  - **空 HTML 页面**（`window.Prism === undefined`）三组对照：旧写法 → `ReferenceError: Prism is not
defined`；语言包排在 guard 之前 → 同样 ReferenceError；现行 `utils/prism-langs.ts` → OK。
  - 应用页首屏：`__errs` 空、`window.Prism` 41 个语言含 python。
  - 生产构建 + `vite preview`：`__errs` 空、41 个语言、python/nginx 都在；产物里守卫
    （`prismGlobal.Prism||(prismGlobal.Prism=Prism$1)`）索引 3682818 在 `languages.scss=`（3683018）之前。
- 常规链路回归：dev 页 `prism.highlight` 跑 python 出真 token（`token keyword` / `token function` /
  `token string-interpolation`）；`vue-tsc -b` exit 0；`vite build` ✓ 9.94s；`vitepress build docs` ✓ 25.78s。
- 反证测试有效：临时删掉 `prism-python` → 用例红；把 `./prism` 挪到语言包之后 → 红（而且直接崩）；
  还原 → 5/5 绿。

**新增回归测试**：`packages/cosey/utils/prism-langs.test.ts`，脚本 `pnpm test:prism`
（`tsx ./packages/cosey/utils/prism-langs.test.ts`）。5 条用例，关键是**不自己抄清单**：
从 `highlight.api.ts` 的 `type Lang*`、`content-code-block.tsx` 的 `languageOptions` 源码里抽语言名，
再逐个查 `prism.languages[x]`。另外还钉住「`./prism` 必须排在语言包之前」和「除 `utils/prism.ts`
外不允许裸引 prismjs 核心」。
写第一版时踩了个坑：顺序那条用 `indexOf('prismjs/components/')` 被文件顶部**注释**里的同名字符串
骗了，改成只扫 `^\s*import\s` 的行。

**踩坑与认知修正**：

- esbuild **单 bundle** 时会把核心的 `var Prism` 提升成模块作用域变量，语言包的裸引用被就近解析到它，
  **测不出这个问题**（第一次拿 esbuild 做对照，两组都「通过」，是假绿）。node/tsx 与浏览器里语言包
  各自是独立模块，才会真实暴露 —— 所以验证必须走浏览器或 node，不能只看 bundle 结果。
- vite `resolve.alias` 用字符串 key 会把 `prismjs/components/*` 一起替换掉，必须用正则精确匹配。
- 敌意环境的对照**不能在加载了 app 的页面上做**：应用启动时就把全局建好了，对照会假绿；
  要另起一个不引 app 的空 HTML。
- 语言包**无法 tree-shake**：prismjs 与 cosey 的 package.json 都没有 `sideEffects` 字段，
  所以合并清单没有「本来能省掉」的体积损失。实测多带 python + json5 + nginx ≈ 4.1 KB raw /
  2.0 KB gzip，且只影响「只引其中一个」的消费方。
