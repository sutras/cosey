## packages/cosey/utils/excel 代码评审（只读，未改代码）

用 tsx + 桩 document 把 `exportExcel` 跑通，产物存 `/tmp/excel-check/`，xlsx 用 openpyxl 严格校验。
结论：分层设计（WorkBook/WorkSheet/Cell + 5 个 serializer + columns2aoa 表头合并）是对的，
三层分组的 rowSpan/colSpan 实测全部正确；但序列化层有 P0：

1. **xlsx 数据单元格引用全为 `r="0"`**：行列号只在 columns2aoa 的表头 Cell 上赋值，
   `aoa2sheet` 造的数据 Cell 保持 `colIndex/rowIndex = -1`，而 `encodeCol(-1)` 静默返回 `''`。
   openpyxl 直接报 `'' is not a valid column name`，判定文件损坏。
2. **`encodeCol(-Infinity)` 死循环**：`noHead: true` + 数据为空时 `Math.max(...[])` = -Infinity，
   `for (col++; col; ...)` 永远为真 → 内存暴涨/OOM，浏览器里是标签页假死。
   （`Math.max(...rows)` 在 20 万行时还会 RangeError。）
3. **多 sheet xlsx 名称与数据错位**：文件写成 `sheet${sheets.length - idx}.xml`，顺序反了，
   `[第一,第二,第三]` 时 sheet1.xml 里装的是第三的数据。
4. **xml / html 序列化完全不转义**：`<a>`、`A&B`、sheet 名 `s&1` 原样拼进 XML；
   html 里 `<img onerror=alert(1)>` 会执行。

P1：csv/txt 无 BOM（Windows Excel 中文乱码）；sharedStrings 用 `indexOf` 线性查找（O(n²)，
8k 行 1.2s、2k→4k→8k 约 4 倍增长）；csv/txt/html/xml 只取 `sheets[0]`，
而 `bookFormats[].sheets` 声明了 multi/single 却无人消费。
P2：`styles.xml` 23.5KB + theme 6.3KB 是整包搬来的 WPS 模板（`cellXfs count=2` 但 cellStyles 引用
xfId 到 48，越界），且没有任何单元格写 `s=` 属性 → 表头无样式、全是死重；
`WorkSheet.insertColumn/deleteColumn/insertRow/deleteRow`、`Cell.style`、`utils.ts` 的 decode\*
半套、`<selection activeCell="O13">` 等为死代码/残留；`footerCount` 走 `obj[colIndex]` 要求统计行是数组。

## 复核真实导出文件 + 兼容性三读数（17:50）

Tiny 反馈「WPS 能正常打开，但 WorkBuddy 预览里很多单元格为空」。实测三个读取器三种表现，同一根因：

- 他的文件 `~/Downloads/导出-20260921173214.xlsx`（19 列，含 C1:E1 分组合并）：数据格全是 `r="0"`，
  `<mergeCells>` 用的是正确坐标 A1:S2 等。
- **WPS**：非法 `r` → 按位置回退，正常显示。位置回退之所以结果正确，是因为导出时把「被合并覆盖的占位格」
  也写进了每一行（`<c r="0"><v></v></c>`），所以每行 cell 的出现顺序 == 真实列序（19 格全对）。
- **WorkBuddy 预览**：丢掉非法 `r` 的格 → 大片空白（Tiny 看到的现象）。
- **openpyxl / calamine（pandas 现代后端）**：直接判损坏 —— `'' is not a valid column name` /
  `Range is missing the expected row component`。

第二个隐性问题（WPS 里也看得见）：数字格陷阱。当前实现在 `wb2xlsx` 里用 `rNum` 判定，
凡是"长得像数字"的**字符串**都写成数字格：`0012` → WPS 显示 12；18 位证件号 →
`1.10101199003071E+17`（末 3 位归零）。Tiny 那份数据里手机号恰好 11 位，所以没暴露。

已在 `/tmp/fixed/utils/excel/`（仓库源码未动）验证过最小补丁，6 处改动：

1. `aoa2sheet` 回填 `colIndex/rowIndex`（根因，2 行）
2. `encodeCol` 对非负整数以外抛错，把「静默变 `''`」改成显式失败
3. sheet 文件名 `sheet${idx + 1}.xml`（原来倒序）
4. 数字格只在 `typeof value === 'number'` 时写，字符串一律 sharedStrings（修前导零/精度/证件号）
5. `sharedStrings` 用 Map 索引替代 `indexOf`（去掉 O(n²)）、`<t xml:space="preserve">` + 转义
6. `dimension` 用 reduce 替代 `Math.max(...rows)`（顺带修 `-Infinity` 死循环的入口）

对比产物：`~/Downloads/excel-导出对比/{当前实现,修复后}.xlsx`（同数据：0012 / 18 位证件号 /
19 位订单号 / 金额）。修复后 openpyxl 与 calamine 都能读，且长数字、前导零原样保留为文本，
表头挂了 `s="1"`（styles.xml 里现成的居中 xf，之前一次都没被用上）。
